# News Search 核心卖点与界面/交互呈现方案

本文档针对 **Octen News Search** 的 4 大核心价值主张（Value Propositions）进行系统性拆解，重点分析当前界面的体现现状，并提出**如何将尚未充分体现的 3 个卖点（更高时效、更全覆盖、更省 Token）在未来产品界面、控制台及动效中优雅落地**的完整方案。

---

## 🧭 四大核心卖点现状评估

| 序号 | 核心卖点 | 官方指标/定义 | 当前 UI / 动效体现现状 | 状态评估 |
| :--- | :--- | :--- | :--- | :--- |
| **1** | **更高时效** | **3 分钟内可搜到**（秒级/分级全网新闻接入与索引） | 仅在时间线卡片有静态绝对时间戳（如 `2026/09/15 21:40:00`），未突出“3 分钟级新鲜度”与“入库延时”感知。 | ⚠️ **需重点强化呈现** |
| **2** | **更全覆盖** | **95% 头部新闻媒体覆盖**（主流通迅社、报刊、财经专线全收录） | 仅在各卡片下方小字展示单一来源域名（如 `Reuters.com`、`Bloomberg.com`），缺乏媒体矩阵与 95% 覆盖率的直观冲击力。 | ⚠️ **需重点强化呈现** |
| **3** | **更省 Token** | **转载去重、相同新闻去重**（去除通稿泛滥，聚合高密事实） | 界面直接展示清洗后的 10 篇最终文章，用户无法感知“在后台过滤掉了多少篇冗余转载、省了多少 Token”。 | ⚠️ **需重点强化呈现** |
| **4** | **话题聚合** | **追踪事件始末**（包含原始事件 + 衍生子事件发展脉络） | 已通过 **Stage 3 主题卡片翻滚 ➔ Stage 4 Top News 聚焦 ➔ Stage 5 时间轴正序延展** 充分体现。 | ✅ **已充分体现** |

## 💡 尚未体现卖点的产品落地与交互设计方案

---

### 卖点 1：更高时效（3 分钟内可搜到 / Wire-Speed Freshness）

#### 为什么重要？
大模型进行实时分析（如突发舆情应对、美联储决议、地缘冲突）时，传统搜索引擎由于爬虫调度周期长，往往需要数小时甚至一天才能收录，而 Octen 能在通讯社发稿 **3 分钟内** 完成全网抓取、解析与向量入库。

#### 建议落地形态：
1. **相对时效徽章（Freshness Badge）**：
   - 在卡片顶部（如 Top News 或最新时间线节点）增加脉冲呼吸绿点与即时相对时差：
     - `● Indexed 2m ago` / `● 1.8 min latency` / `● Wire Speed: Ingested in 110s`；
   - 相比传统的冰冷日期 `2026/09/15`，高亮绿点与“刚刚发生/分钟级入库”能瞬间传递实时感。
2. **检索中（Stage 2）的快报扫描动态感知**：
   - 在 Stage 2 Searching 阶段的加载动效或状态副标题中加入提示：
     - *“Scanning 12,000+ real-time wire dispatches from the last 3 minutes...”*
3. **左侧信息面板指标补充**：
   - 在左侧信息栏（包含 `4 subjects`、`10 articles`）上方或下方补充关键性能指标胶囊：
     - `Latency: < 3 min` 或 `Freshness: Real-Time Wire (<3m)`。

---

### 卖点 2：更全覆盖（95% 头部新闻媒体覆盖 / Comprehensive Tier-1 Coverage）

#### 为什么重要？
企业级 AI 与投研机构最忌讳“野鸡信源”或“信息盲区”。覆盖 95% 头部媒体意味着涵盖路透社、彭博、美联社、华尔街日报、金融时报等权威机构，输出的是权威、经得起合规检验的高置信度情报。

#### 建议落地形态：
1. **头部信源 Favicon 矩阵 / 聚合来源折叠标签**：
   - 在时间线卡片或 Top News 卡片来源旁，展示权威媒体的品牌图标或 Logo 微标（如 Bloomberg、Reuters、CNBC、WSJ、Al Jazeera 等）；
   - 在左侧面板的统计数据中增加信源广度维度：
     - 原文：`4 subjects · 10 articles`
     - 升级方案：`4 subjects · 10 articles · 8 tier-1 sources`；
2. **“95% Tier-1 Verified” 信任背书印记**：
   - 在巨幅卡片左下角或左侧面板标题旁增加品质认证小微标：
     - `[ ✓ 95% Tier-1 News Sources ]`；
   - Hover 时浮动展示信源覆盖清单 Tooltip（如收录 5,000+ 权威国际通讯社与财经专线）。

---

### 卖点 3：更省 Token（转载去重、相同新闻去重 / High-Density Token Deduplication）

#### 为什么重要？
在真实网络环境中，一篇美联社通稿会被几百家小媒体全文转载，传统搜索将大量重复文本喂给 LLM 会导致：
1. **上下文窗口急剧膨胀**（浪费 70%~90% 的 Context Token）；
2. **模型注意力稀释**（迷失在多份雷同新闻中，推理成本激增）。
Octen 通过指纹去重与事件语义折叠，将几十篇雷同稿压缩合并为单一核心事实节点，**大幅降低 API Token 消耗并提升推理质量**。

#### 建议落地形态：
1. **去重压缩比率徽章（Dedup / Token Savings Badge）**：
   - 在卡片顶部或左侧摘要栏展示去重前后数据对比：
     - `Dedup: 10 clean articles from 86 wire feeds (-78% Token Waste)`；
     - 或直接在卡片底部以小字胶囊呈现：`⚡ 74 duplicates pruned · Saved ~18,400 Tokens`。
2. **通稿归拢（Syndication Cluster）微交互**：
   - 在主新闻卡片底部显示转载来源折叠提示：
     - `“+6 syndicated outlets (Yahoo Finance, MSN, MarketWatch...)”`；
   - 用户点击或悬浮时可轻量展开看到被合并的转载渠道，证明系统自动做了语义归并，而非丢失了信源。
3. **“Raw vs Octen” Token 消耗对比面板（可选控制台/官网营销展示）**：
   - 在功能展示区或弹窗中对比：
     - 传统搜索喂给 Agent：**45,000 tokens**（大量重复通稿与无用网页模版）；
     - Octen 结构化交付：**3,200 tokens**（纯净事实核验流，节省 **92%** Token 预算）。

---

### 卖点 4：话题聚合（追踪事件始末 / Event Lineage Tracking）

#### 现有基础与进阶建议：
- **现有实现**：
  - Stage 3 展示按事件聚类的 4 大横向卡片（Subject 1~4）；
  - Stage 5 时间轴依时间正序展示该事件由浅入深的报道链条。
- **进阶升级方向**：
  - **因果/阶段拓扑标记**：为时间线节点打上结构化角色标签：
    - `[ 始发事件 / Origin ]` ➔ `[ 官方声明 / Response ]` ➔ `[ 衍生影响 / Escalation ]` ➔ `[ 市场反应 / Market Reaction ]`；
  - 明确展现从“原始突发事件”到“后续多分支子事件”的衍生关系，使 LLM 能精准还原因果链条。

## 📋 总结与落地优先级规划

| 卖点 | 推荐落地方案 | 复杂度 | 视觉收益 | 推荐优先级 |
| :--- | :--- | :---: | :---: | :---: |
| **更省 Token** | 在左侧面板或卡片顶部加入 **Token 压缩比与去重统计**（如 `Saved ~18k Tokens`、`86 wires consolidated to 10`） | 低~中 | ⭐⭐⭐⭐⭐（直接打动开发者与企业决策者） | **P0（最高）** |
| **更高时效** | 将卡片时间由静态绝对时间优化为 **`● Ingested 2m ago` / `Latency <3m` 呼吸绿点徽章** | 低 | ⭐⭐⭐⭐⭐（直观感受秒级网络新鲜度） | **P0（最高）** |
| **更全覆盖** | 增加 **8+ 头部媒体 Logo / Favicon**，并将统计栏扩展为包含信源维度 | 低 | ⭐⭐⭐⭐（强化权威度与可信赖感） | **P1** |
| **话题聚合深化**| 在时间线卡片上增加 **`Origin` / `Escalation` 原始与子事件拓扑标签** | 中 | ⭐⭐⭐⭐（强化叙事因果与推理链条） | **P2** |
